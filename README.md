# stock-picker — 配当株の買い場

高配当・優待目的で長く持つ銘柄（本人の区分でいう②）について、
**良い銘柄が安くなっていないか**を月に1回ほど眺めるためのページ。
売買は行わない。候補と判断材料を並べるだけ。

ページ: https://momomo4183.github.io/stock-picker/ （GitHub Pages で公開）

## 使い方

デスクトップの「**配当株の買い場 更新**」をダブルクリックする。
株価の取り直し → 条件で絞る → ページ作成 → GitHub へ反映 まで自動で進み、
終わるとPC上でページが開く。スマホのページは1分ほど遅れて変わる。

```
run_update.bat            通常の更新（約1〜2分）
run_update.bat --full     1株あたりの値（EPS・BPS・配当）も必ず取り直す
run_update.bat --no-push  GitHub に反映せず手元で確認する
```

1株あたりの値は7日より古いと自動で取り直す。その回だけ10〜30分かかる
（1社ずつ問い合わせるため）。

## 候補の条件

PER12以下・PBR1以下・配当利回り3%以上・時価総額700億円以上
（楽天証券スーパースクリーナーに保存していた条件そのまま）

## 並べている判断材料

| 列 | 意味 |
|---|---|
| 割安度 | 今の配当利回りが、その銘柄の過去5年の中でどれだけ高いか（0〜100）。高いほど配当に対して株価が安い。既定の並び順 |
| 荒さ | 値動きの大きさの、全銘柄の中での位置（穏やか／普通／荒い） |
| 減配 | 過去5年で年間配当が前年を下回った回数（記念配当の翌年も数える） |
| 連続増配 | 直近まで何年続けて年間配当が増えているか |
| 配当性向 | 利益のうち配当に回している割合 |
| 権利月 | 配当の権利が確定する月（直近1年の実績） |

「荒さ」を入れたのは検証の結果による。値上がりする銘柄を選ぶ条件は、
探索期間と検証期間に分けて3回試して3回とも検証期間で崩れた。一方、
**値動きが穏やかな銘柄は「1年後に−20%以下になっている確率」が
18%→5〜8%に下がり、前半・後半どちらの期間でも同じように効いた**
（`backtest/` 参照）。1年以上持つ前提の銘柄選びに向いた指標。

株主優待は取得できないので含まない。
**公開ページなので、保有銘柄などの個人情報は載せない。**

## データの出どころ

| データ | 出どころ | 取り直す頻度 |
|---|---|---|
| 株価（日足6か月・全銘柄） | yfinance | 更新のたび（約1分） |
| 1株あたりの値（EPS・BPS・株式数・配当） | yfinance | 7日より古ければ |
| 候補の株価6年分と配当履歴 | yfinance | 更新のたび（候補の50〜60銘柄だけ） |
| 銘柄一覧 | JPX 東証上場銘柄一覧 | 月1回程度 |

PER・PBR・時価総額・配当利回りは「その日の株価 × 1株あたりの値」で計算する
（yfinance の値との一致は PER 99.8% / PBR 99.9% / 時価総額 99.8% が誤差1%以内）。
株価の取得は自宅PCから行う。Yahoo はデータセンターからの接続を拒否するため、
GitHub Actions やクラウドでは取得できない（2026-09-18 に確認）。

## ファイル

```
run_update.bat                ダブルクリックで更新
scripts/update.py             更新の手順をまとめて実行し、GitHub に反映する
scripts/fetch_data.py         株価・1株あたりの値の取得
scripts/retry_fundamentals.py 取得制限で失敗した分を1社ずつ取り直す
scripts/build_site.py         条件で絞り、配当の材料を足してページを作る
backtest/                     条件の検証（過去14年）。結果は backtest/結果/
data/                         取得したデータ（リポジトリには含めない）
docs/                         公開するページ
```
